# Superpowers Orchestrator

Система агентной разработки с субагентами, ролями и поведенческими скиллами. Оркестратор-агент получает задачу, классифицирует сложность, декомпозирует на подзадачи и последовательно делегирует специализированным субагентам — каждый из которых динамически загружает свою роль (персону) и набор скиллов (SOP) через MCP-сервер.

## Что внутри

- **120+ специализированных ролей** — engineering, design, marketing, testing, sales, game dev и другие домены. Каждая роль — готовая персона с инструкциями для AI-агента
- **Поведенческие скиллы** — TDD, systematic debugging, code review, parallel dispatch, verification before completion и другие стандартные операционные процедуры
- **Оркестратор (Engineering Manager)** — скилл, превращающий агента в лида: триаж задач (Trivial → Epic), декомпозиция, делегирование с обязательной загрузкой профильных скиллов субагентом
- **MCP-сервер** — stdio-сервер, отдающий роли и скиллы через [Model Context Protocol](https://modelcontextprotocol.io/).
- **Автоматический установщик** — определяет IDE, копирует ресурсы, регистрирует MCP-сервер

## Концепции системы

Понимание архитектуры поможет эффективно использовать систему:

### 1. Оркестратор (Engineering Manager)
Это «главный агент» или «лид». Его задача — не писать код самому, а управлять процессом. Он анализирует запрос пользователя и решает, как его лучше реализовать.

### 2. Триаж (Triage)
Процесс оценки сложности задачи. Оркестратор классифицирует задачу по 4 уровням:
- **Trivial**: Простые правки (1 файл, <30 строк).
- **Small**: Небольшие задачи (1-3 файла).
- **Standard**: Полноценные фичи (несколько модулей, API).
- **Epic**: Крупные проекты (>5 задач, кросс-зависимости).

### 3. Роли (Roles)
Профили специалистов (например, `engineering-frontend-developer`). Содержат контекст, стандарты и ограничения для конкретной специализации. Агент «становится» этой ролью при выполнении задачи.

### 4. Скиллы (Skills)
Стандартные операционные процедуры (SOP). Определяют *как* агент должен выполнять работу (например, `test-driven-development` или `systematic-debugging`).

### 5. Субагенты
Инстансы агентов, которым Оркестратор делегирует конкретные шаги. Каждый субагент получает свою Роль и Скилл через MCP-инструменты.

## Сценарии использования

### Сценарий 1: Разработка новой фичи (Standard)
1. Пользователь: «Добавь аутентификацию через Google в проект».
2. Оркестратор (Триаж): Определяет уровень `Standard`.
3. Оркестратор (Декомпозиция): Создает цепочку TODO: [Спроектировать API, Настроить OAuth, Обновить UI...].
4. Делегирование: Вызывает субагента с ролью `backend-developer` и скиллом `api-design`.
5. Субагент выполняет шаг, возвращает результат.

### Сценарий 2: Исправление бага (Small)
1. Пользователь: «Исправь ошибку в валидации формы на странице логина».
2. Оркестратор: Уровень `Small`.
3. Делегирование: Субагент с ролью `frontend-developer` и скиллом `systematic-debugging`.
4. Результат: Быстрое исправление и код-ревью.

### Сценарий 3: Рефакторинг (Epic)
1. Пользователь: «Перепиши модуль оплаты на микросервисы».
2. Оркестратор: Уровень `Epic`.
3. Действие: Глубокая декомпозиция, создание плана миграции, последовательное делегирование разным командам агентов (DBA, Backend, DevOps).

## Пошаговое руководство по работе

### Техническая настройка
1. **Установка**: Выполните скрипт установки, чтобы зарегистрировать MCP-сервер в вашей IDE (VS Code, Cline, RooCode).
   ```bash
   node install.js
   ```
2. **Проверка**: Убедитесь, что в настройках MCP вашей IDE появился сервер `superagents-mcp`.

### Взаимодействие в чате
1. **Постановка задачи**: Опишите задачу максимально четко. Оркестратор сам определит сложность.
   - *Плохо*: «Сделай сайт».
   - *Хорошо*: «Создай компонент карточки товара на Next.js с использованием shadcn/ui, принимающий пропсы: title, price, image».
2. **Мониторинг**: Оркестратор будет сообщать о переходах между этапами (Триаж → Декомпозиция → Делегирование).
3. **Принятие работы**: После выполнения всех пунктов TODO, Оркестратор предложит результат. Используйте `attempt_completion`, чтобы зафиксировать итог.

## Примеры взаимодействия с агентами

### Вызов роли через MCP
Когда Оркестратор делегирует задачу, он использует инструменты MCP:
```typescript
// Оркестратор запрашивает роль для субагента
get_role({ role_id: "engineering-frontend-developer" })

// Оркестратор запрашивает скилл для процедуры
get_skill({ skill_id: "test-driven-development" })
```

### Поток данных
```text
[Пользователь] -> "Сделай кнопку"
     |
[Оркестратор] -> Триаж: Trivial
     |
[Оркестратор] -> get_role("engineering-frontend-developer")
     |
[Субагент] -> Получает контекст роли и пишет код
     |
[Оркестратор] -> Проверка (Verification skill)
     |
[Пользователь] <- Готовая кнопка
```

## Советы по эффективному использованию

1. **Будьте конкретны**: Указывайте технологический стек (React, Python, Go) прямо в запросе. Это поможет Оркестратору выбрать правильную роль.
2. **Используйте теги**: Если вы знаете нужный скилл, упомяните его (например, «сделай это через TDD»).
3. **Доверяйте декомпозиции**: Не пытайтесь сами разбивать Epic-задачи. Оркестратор сделает это лучше, используя внутренние алгоритмы.
4. **Экономьте токены**: Используйте скилл `caveman`, если нужно сократить расход токенов в длинных диалогах (сообщения будут короткими, как у пещерного человека, но технически точными).
5. **Проверка контекста**: Если агент «забыл» контекст, попросите его вызвать `list_roles` или `search_roles` для обновления списка доступных специализаций.

## Быстрый старт

### Требования
- Node.js ≥ 18

### Установка
```bash
git clone https://github.com/kononenko/superpowers-orchestrator.git
cd superpowers-orchestrator
npm install
npm run build
node install.js
```

Установщик автоматически:
1. Копирует роли в `~/.superpowers-orchestrator/roles`
2. Копирует скиллы в `~/.superpowers-orchestrator/skills` и публичные — в `~/.agents/skills`
3. Регистрирует MCP-сервер `superagents-mcp` в настройках обнаруженной IDE

### Обновление
```bash
node update.js
```

### Ручная конфигурация MCP-клиента
Если установщик не обнаружил IDE, добавьте вручную в настройки MCP:
```json
{
  "mcpServers": {
    "superagents-mcp": {
      "command": "superagents-mcp",
      "args": [],
      "env": {
        "SUPERPOWERS_ROLES_PATH": "~/.superpowers-orchestrator/roles"
      }
    }
  }
}
```
Подробные инструкции: [workflows/cline.md](workflows/cline.md), [workflows/roocode.md](workflows/roocode.md).

## Как это работает (технический процесс)

```
Пользователь → Оркестратор (Engineering Manager skill)
                    │
                    ├─ Триаж: Trivial / Small / Standard / Epic
                    ├─ Декомпозиция → TODO-цепочка
                    │
                    └─ Делегирование субагентам:
                         ├─ get_role("engineering-frontend-developer")  → персона
                         ├─ get_skill("test-driven-development")        → SOP
                         └─ субагент выполняет задачу по роли + скиллам
```

### Уровни триажа
| Уровень | Признаки | Маршрут |
|---------|----------|---------|
| **Trivial** | 1 файл, ≤30 строк, без новой логики | Fast-Path — один вызов code-субагента |
| **Small** | 1–3 файла, дизайн очевиден | Short-Path — code + review |
| **Standard** | Новая фича, несколько модулей, API | Full SOP — spec → plan → implement → review |
| **Epic** | >5 тасков, кросс-зависимости | Decompose & Loop |

## MCP Tools
| Tool | Параметры | Описание |
|------|-----------|----------|
| `get_role` | `role_id` | Полная роль с YAML frontmatter и markdown content |
| `list_roles` | `filter?`, `domain?`, `tags?` | Список ролей (метаданные, без content) |
| `search_roles` | `query` | Поиск по id, name, description (подстрока, регистронезависимый) |
| `get_domains` | — | Уникальные домены: engineering, testing, design, marketing… |
| `get_skill` | `skill_id` | Содержимое SKILL.md по идентификатору |
| `list_skills` | — | Список всех доступных скиллов |

## MCP Resources
| URI | MIME | Описание |
|-----|------|----------|
| `roles://index` | `application/json` | Полный индекс ролей (метаданные) |
| `roles://{role_id}` | `text/markdown` | Конкретная роль |

## Структура проекта
```
superpowers-orchestrator/
├── src/
│   ├── index.ts              # Entry point (stdio MCP server)
│   ├── server.ts             # Инициализация MCP, регистрация tools/resources
│   ├── tools/                # Реализация MCP tools
│   └── utils/                # Парсер ролей, индексатор, конфиг
├── roles/                    # 120+ ролей (YAML frontmatter + MD)
├── skills/
│   ├── behavioral/           # Поведенческие скиллы (TDD, debugging, review…)
│   ├── super-orchestrator/   # Скилл Engineering Manager оркестратора
│   └── caveman/              # Token-saving communication mode
├── workflows/                # Инструкции для Cline / RooCode
├── install.js                # Кроссплатформенный установщик
└── update.js                 # Обновление ролей и скиллов из репо
```

## Формат роли
Каждая роль — `.md` файл с YAML frontmatter:
```markdown
---
id: engineering-frontend-developer
name: Frontend Developer
description: Специалист по React/Next.js
domains: [engineering]
tags: [react, nextjs, typescript]
---

# Frontend Developer

Инструкции для агента...
```
